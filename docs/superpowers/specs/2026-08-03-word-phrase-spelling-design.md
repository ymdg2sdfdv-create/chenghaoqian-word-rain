# 单词与短语差异化拼读设计

## 背景

当前拼读阶段统一使用字符数组遍历词条。这个做法适合普通单词，但会把短语中的空格、括号和占位省略号也当成拼读步骤，造成无意义的发音调用和固定时长等待。

本次修改只调整拼读阶段的拆分、显示、发音与等待规则，不改变完整揭示、中文提示、自动提取、快速识别、复习调度和进度存储。

## 目标规则

1. 普通单词按字母拼读。
2. `cat` 为 `phrase` 的短语按英文单词块拼读。
3. 空格、左右括号、三个句点组成的占位省略号和单字符省略号不发音，也不产生等待。
4. 被括号包围的英文单词仍然是可发音单词块；只有括号符号本身被跳过。
5. 拼读过程中保留原词条的视觉文本，非发音符号可随相邻单元一起出现在累计显示内容中。

## 示例

| 原词条 | 拼读单元 | 不发音、不等待 |
|---|---|---|
| `present` | `p`, `r`, `e`, `s`, `e`, `n`, `t` | 无 |
| `go through` | `go`, `through` | 空格 |
| `keep ... going` | `keep`, `going` | 空格、`...` |
| `be supposed (to)` | `be`, `supposed`, `to` | 空格、`(`、`)` |

## 设计

### 拼读单元解析器

在播放层增加一个纯解析函数，输入完整课程条目，输出有序拼读步骤。每个步骤至少包含：

- `spokenText`：本次需要发音的字母或英文单词块。
- `visibleText`：执行本步骤时应累计显示的原始词条片段。

解析规则：

- 非短语条目逐个处理英文字母，形成字母步骤。
- 短语条目提取连续英文字母组成的单词块，形成单词块步骤。
- 分隔符不单独形成步骤，而是合并进相邻步骤的累计显示范围。
- 若词条末尾只有被忽略符号，则这些符号随最后一个有效步骤显示。
- 解析器不修改 `word-bank-data.js`，也不修改条目的 `word` 原值。

### 播放流程

现有拼读循环改为遍历解析后的步骤：

1. 显示该步骤对应的累计原始文本。
2. 播放一次视觉节拍和短音效。
3. 发音 `spokenText`。
4. 普通单词继续采用现有字母节拍时长。
5. 短语等待当前单词块发音结束后再进入下一块；如音频不可用且语音回退失败，则使用现有的短暂静默兜底，避免流程卡住。
6. 所有步骤结束后进入现有完整词条揭示流程。

短语单词块发音优先使用浏览器英文语音，因为本地完整词条音频以整条短语命名，不提供各组成单词的独立文件保证。完整揭示和快速识别仍优先播放原有整条短语 MP3。

### 与暂停、静音的关系

- 每个拼读步骤开始前继续通过现有运行令牌和暂停门控制。
- 静音时仍推进视觉步骤；普通单词使用字母节拍，短语在无法获得实际发音完成事件时使用短暂静默兜底。
- 停止或重新开始课程时，旧拼读循环继续通过现有运行令牌失效，不引入新的全局状态。

## 错误处理

- 没有可发音英文内容的异常词条不得造成死循环；解析器返回空步骤时直接进入完整揭示。
- 单个短语词块发音失败时继续后续词块，不中断整个词条。
- 未知 `cat` 按普通单词规则处理，保持现有行为。

## 测试与验收

### 解析测试

- 普通单词只产生字母步骤。
- 普通短语只产生单词块步骤。
- `keep ... going` 只产生 `keep`、`going` 两个发音步骤。
- `be supposed (to)` 只产生 `be`、`supposed`、`to` 三个发音步骤。
- 每个示例最终累计显示文本与原始 `word` 完全一致。

### 播放测试

- 普通单词保持逐字母发音和原有节奏。
- 短语每个单词块只发音一次，上一块完成后才进入下一块。
- 空格、括号和两种占位省略号没有发音调用，也没有独立等待。
- 拼读完成后的整词英文、中文、回忆和快速识别流程保持不变。
- 拼读中暂停后不会继续推进，恢复后从当前流程继续；重新开始后旧流程不会复活。

## 非目标

- 不修改词库内容、词条分类或音频文件命名。
- 不为短语组成单词批量生成新的本地 MP3。
- 不改变拼读轮数、复习间隔、快速识别次数或页面视觉风格。
