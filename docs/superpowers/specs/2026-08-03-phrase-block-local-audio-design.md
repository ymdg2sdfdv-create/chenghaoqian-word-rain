# 短语单词块本地音频优先设计

## 背景

差异化拼读功能已经将普通单词拆成字母、将短语拆成英文单词块。当前短语单词块直接调用浏览器 TTS，因此可能与完整词条使用的 `en-US-GuyNeural` 本地 MP3 声线不一致。

DeepSeek 已补充 80 个缺失的短语组成词音频。经检查，100 个短语涉及的 108 个唯一单词块现已全部拥有对应的本地 MP3，覆盖率为 100%。

## 目标

短语拼读阶段的每个英文单词块优先播放 `assets/audio/words-en/<单词>.mp3`，仅当文件无法加载或播放时才回退到浏览器英文 TTS。

## 设计

### 复用现有音频接口

现有 `speakEN(text)` 已实现以下顺序：

1. 根据单词文本生成安全文件名。
2. 尝试播放 `assets/audio/words-en/<文件名>.mp3`。
3. 本地文件加载或播放失败时，调用浏览器英文 TTS。
4. 返回 Promise，并在本地 MP3 或 TTS 播放结束后完成。

因此不新增专用播放器。短语拼读循环只需将单词块的发音调用从直接使用 `fallbackTTS(step.spokenText, "en-US")` 改为 `speakEN(step.spokenText)`。

### 播放流程

短语 `keep ... going` 的一轮拼读流程为：

1. 显示 `keep ... `，播放 `assets/audio/words-en/keep.mp3` 并等待结束。
2. 空格和 `...` 不产生发音调用或独立等待。
3. 显示 `keep ... going`，播放 `assets/audio/words-en/going.mp3` 并等待结束。
4. 进入现有完整揭示流程，播放完整短语 MP3 和中文 MP3。

普通单词的逐字母 TTS、完整词条揭示、中文提示、回忆和快速识别保持不变。

### 回退与异常

- 单词块本地 MP3 不存在、损坏或被浏览器拒绝播放时，自动回退浏览器英文 TTS。
- TTS 也失败或处于静音状态时，沿用现有 `silentFlashMs` 静默兜底，避免流程卡住。
- 暂停、继续、停止和运行令牌继续使用现有音频控制逻辑，不新增全局状态。

## 音频资产约束

- 80 个新增文件保留在 `assets/audio/words-en/`。
- 文件名为小写英文单词，不包含空格、括号或省略号。
- 不重新生成已有普通词、完整短语、中文或反馈音频。
- 新增音频与代码可在同一功能分支交付，但提交应按资产与代码分开，便于审查。

## 测试与验收

### 自动测试

- 短语单词块调用 `speakEN`，而不是直接调用 `fallbackTTS`。
- 本地音频成功时等待 `speakEN` 完成后才进入下一单词块。
- 本地音频失败并由 TTS 成功时仍正常进入下一单词块。
- 本地音频和 TTS 都失败时执行一次静默兜底后继续。
- 普通单词仍使用现有逐字母路径。
- 108 个短语单词块均能映射到非空本地 MP3。

### 页面验收

- 抽测 `go through`、`keep ... going` 和带括号短语。
- 每个单词块完整播放后才进入下一块。
- 空格、括号、`...`、`…` 无声音、无独立停顿。
- 完整短语及中文仍在揭示阶段播放。
- 暂停、继续和静音不造成流程卡死或重叠播放。

## 非目标

- 不拼接或重新生成完整短语音频。
- 不改变短语解析规则、视觉显示、拼读轮数或复习流程。
- 不移除浏览器 TTS 回退能力。
